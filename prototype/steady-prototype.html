    The loop

    How a distraction turns into a study rep

    The schedule starts strict mode, so the user never has to start it themselves. Every urge is caught on the phone and offered three exits. The easiest exit is closing the app.

    How it works underneath

    One set of rules, enforced differently on each device

    The rules engine lives on the phone and syncs schedules, not screen contents. Each platform uses the strongest blocking it officially allows, and steps down to a simpler block if Instagram or YouTube changes its layout.

    Rules engine

    Schedules, blocked surfaces, key holder, unlock costs. Synced across devices.

    Detector updates

    Pushed as remote config with health checks, so a layout change in Instagram is fixed in hours, not an app release.

    Honest status

    If blocking gets weaker, the user sees “Reels detection paused, whole app blocked instead.”

    Android

    1. Hide Reels and Shorts inside the app (Accessibility, with clear disclosure)
    2. Fallback: block the whole app
    3. Fallback: block by domain on the phone

    Risk: Play policy and Android 17 Advanced Protection can turn off Accessibility.

    iOS

    1. Screen Time API blocks whole apps on schedule
    2. Shortcuts automation shows the breath screen
    3. Web Shorts hidden in Safari extension

    Limit: Apple doesn’t allow hiding only part of another app. We say so up front.

    Chrome / laptop

    1. Extension hides Shorts shelf and Reels on web
    2. Site blocks follow the same schedule
    3. Same unlock cost and key holder

    Most durable layer. Closes the “I’ll just use my laptop” loophole.

    Key holder

    1. Friend or parent gets bypass alerts only
    2. Approves emergency unlocks
    3. Weekly summary, never content

    Parent-held key fits Indian students; consent rules apply under 18.
